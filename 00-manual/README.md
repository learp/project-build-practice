# 00-manual — проект БЕЗ системы сборки

Одно и то же консольное приложение — **log-stats, анализатор логов** —
которое в соседних директориях (`../01-maven/`, `../02-gradle/`) собирается
одной командой, здесь собирается руками: `javac`, `jar`, classpath из банок,
скрипт. Легенда: `samples/app.log` — реальный кусок лога прод-сервиса
веб-звонков (signaler), который «прислал коллега».

Требуется JDK 21+.
CLI: `./run.sh <file.log> [--top N]`

## Структура

```
00-manual/
├── src/best/project/ever/     # Main, LogParser, LogStats, JsonReportWriter, Report
├── samples/app.log            # реальный лог прод-сервиса (signaler) — вход
├── resources/logback.xml      # конфиг логирования
├── lib/                       # либы, скачанные вручную
├── incoming/gson-2.15.0.jar   # «коллега принёс обновление»
├── run.sh                     # весь ручной путь, застывший в скрипте
└── out/                       # генерируется: классы, logback.xml, logstats.jar
```

5. Сколько мест в проекте надо поменять, чтобы обновить Gson? (Посчитайте

## Замечание для Windows

Разделитель classpath на Unix — `:`, на Windows — `;`. Скрипт придётся
переписать. Это тоже пункт в копилку «зачем нам система сборки».
