# jenkins/ — локальный Jenkins для лекции

Материалы к сегменту Jenkins практики «Непрерывная интеграция»:
контроллер с UI, который сам же выполняет сборку. В проде так не делают
(ставят отдельных агентов), для лекции достаточно.

## Подготовка (один раз, ~5 минут + ожидание)

```bash
docker build -t jenkins-lecture .
docker run -d --name jenkins -p 8080:8080 -v jenkins_home:/var/jenkins_home jenkins-lecture

# Пароль начального администратора:
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
```

Открыть `http://localhost:8080`, войти, выбрать плагины по умолчанию
(нужные уже в образе), создать пользователя `lecturer`.

## Джоба (один раз)

New Item → **log-stats**, тип **Pipeline**:

- Definition: *Pipeline script from SCM*
- SCM: Git → Repository URL: `https://github.com/learp/project-build-practice.git`
- Branch: `*/main` (или ветка, где идёт репетиция)

Jenkinsfile уже в корне репо — он подхватится сам.

## Прогрев volume (обязательно до лекции)

Запустить джобу один раз и дождаться зелёного: первый запуск скачает
Gradle 9.2.1 и зависимости в `jenkins_home`. Критерий готовности:
**повторный запуск зелёный за ≤ 2 минут**.

Контейнер не пересоздавать между прогревом и лекцией — прогретый
volume живёт в named volume `jenkins_home` (образ можно пересобирать,
volume переживёт; `docker volume rm` — нельзя).

## Что показывается на лекции (7–10 минут)

1. Архитектура на живом экране: контроллер с UI, который сам выполняет
   сборку — «в проде так не делают, ставят агентов» (слайды 29–31).
2. Открыть Jenkinsfile рядом с `ci.yml` — декларативный синтаксис,
   `agent any`, `stages`, `post.always`.
3. Запуск руками (Build Now) — ручной триггер со слайда про триггеры.
4. Синий шарик → Console Output: те же `> Task :compileJava`, что в
   GitHub. «То же самое, только UI из 2011-го — и в этом тоже правда жизни».
5. Артефакт в post: `archiveArtifacts` — аналог `upload-artifact`.

## Проверено / не проверено

- Образ собирается: да (docker build, 14.11.2026 — см. журнал подготовки).
- Джоба зелёная ≤ 2 мин: **не проверено** — прогрев и критерий на
  утренней проверке (нужен первый живой запуск).
